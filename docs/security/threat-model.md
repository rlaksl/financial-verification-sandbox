# 위협 모델

기준일: 2026-11-26 · 관련 결정: D-T01 ~ D-T10

## 1. 문서의 역할

방어 범위를 정의한다. 방어 수단의 선택은 [결정·상태 대장](../decision-register.md), 해결할 문제는 [기술 쟁점 대장](../research/technical-issues.md), 검증 방법은 [PoC 계획](../poc/plan.md)에서 다룬다.

이 문서는 확정 상태이며(D-T06), 이후 발견되는 세부 문제는 해당 기술의 상세 설계·검증 항목으로 관리한다. 이 문서의 방어 수단은 아직 실행으로 검증되지 않았다.

## 4. 공격자 모델

### 4.1 외부 경로·고객사 측 공격자 (A)

| ID | 능력 | 방어 목표 | 방어 전제 | 잔여 위험 |
| --- | --- | --- | --- | --- |
| A1 | Access Token만 탈취 | 예방: 탈취한 토큰을 단독으로 사용할 수 없음 | 모든 토큰이 발신자 제한됨, 바인딩 없는 토큰을 받지 않음 | 전제 충족 시 없음 |
| A2 | 토큰과 인증 증명을 사후에 탈취해 재전송 | 예방: 이미 사용한 증명을 다시 수락하지 않음 | 재전송 기록의 신뢰성(D-X50), 증명의 제한된 수락 기간 | 아래 "재전송의 두 유형" |
| A3-a | 고객사와 Sandbox 사이에서 TLS 검사 장비 등 평문 요청에 접근할 수 있는 중간 구성요소를 침해해 요청을 열람·변조 | 탐지·차단: 업무 API와 토큰 엔드포인트의 요청 위변조 | 고객사 인증 개인키, 메시지 서명 개인키, 토큰 바인딩 개인키, Sandbox 애플리케이션은 장악하지 않음 | 기밀성·가용성은 필수 보장 아님. 응답 무결성은 연구 대상 |
| A3-b | Sandbox 앞단 프록시 또는 전달 구간을 침해 (프로세스 침해, 설정 변조, 전달 구간 변조) | 탐지·차단: 위와 같음 | TA-3. 위와 같은 키·애플리케이션 미장악 | 위와 같음. 프록시가 생성한 오류 응답은 보호 대상 밖 |
| A4-a | 고객사 인증 자격 증명(인증 키 또는 인증서 개인키) 유출 | 사고 대응: 해당 자격 증명 무효화와 관련 토큰 연쇄 폐기 | 자격 증명과 발급 토큰의 연결 기록(T-26), 신뢰를 줄이는 변경의 즉시 반영(D-B04) | 탐지·폐기 전까지 사칭 가능 |
| A4-b | 토큰 바인딩 키 유출 (DPoP 키 또는 바인딩에 쓰는 TLS 인증서 개인키) | 사고 대응: 해당 키에 묶인 토큰 폐기 | 바인딩 키 기준 폐기 수단 | 아래 "바인딩 키 유출의 구분" |

**A3-a는 단순한 네트워크 경로상의 공격자가 TLS 평문에 접근할 수 있다는 의미가 아니다.**

**A3-a, A3-b, A5의 침해 범위**

| 공격자 | 침해한 것 | 침해하지 않은 것 | 경계 |
| --- | --- | --- | --- |
| A3-a | 고객사 측 평문 접근 중간 구성요소 | 고객사 서버, 고객사 개인키, Sandbox | TB-1 바깥이지만 고객사 통제 영역 |
| A3-b | Sandbox 측 프록시·전달 구간 | Sandbox 애플리케이션, 키 저장소 | TB-2 ~ TB-3 사이 |
| A5 | 고객사 서버 자체 | Sandbox | TB-1 안쪽 |

**mTLS와 고객사 TLS 검사 환경**: 종단 간 mTLS가 고객사의 TLS 검사 환경과 호환되지 않으면 보안 정책을 낮추지 않는다. 연결을 거부하거나 고객사 측의 검사 예외 경로가 필요하다.

**토큰 발급 요청의 무결성**: A3의 범위에는 업무 API뿐 아니라 토큰 엔드포인트가 포함된다. 업무 API의 메시지 서명만으로 토큰 발급 과정이 보호된다고 가정하지 않는다. 고객사 인증, 토큰 바인딩, 요청 전체 무결성, 재전송 방어, 응답 무결성은 서로 다른 속성이다(D-T10). Client Assertion과 DPoP Proof가 서로 묶여 있지 않으면 경로 공격자가 유효한 Assertion을 유지한 채 Proof만 자신의 키로 바꿔 먼저 도착시킬 수 있다(T-25). 이 바인딩을 해결해도 scope 등 나머지 파라미터의 무결성은 별도 문제다.

**재전송의 두 유형 (A2)**

| 유형 | 내용 | 보장 |
| --- | --- | --- |
| 이미 사용한 증명의 재전송 | 수락된 증명을 다시 보냄 | 재전송 기록으로 거부 |
| 최초 수락 이전의 경쟁 | 탈취한 증명으로 정상 요청보다 먼저 도착 | 같은 증명의 동시 요청 중 최대 한 건만 수락. 정상 요청이 그 한 건이 된다는 보장은 없다 |

계열별 재전송 대상: M-1·M-2는 TLS 1.3 0-RTT Early Data(T-28), M-3는 Client Assertion(T-01)과 0-RTT, D는 Client Assertion·DPoP Proof·메시지 서명 재전송 식별자. M 계열에 재전송 대상이 없다고 일반화하지 않는다.

**바인딩 키 유출의 구분 (A4-b)**

| 상황 | 결과 |
| --- | --- |
| 바인딩 키만 유출 | 발급된 토큰을 따로 확보하지 못하면 사용할 토큰이 없다. 새 토큰 발급에는 고객사 인증이 추가로 필요하다 |
| 바인딩 키와 해당 Access Token을 함께 확보 | 폐기 전까지 해당 토큰 사용 가능 |
| 인증과 바인딩에 같은 자격 증명을 쓰는 계열(M-1, M-2) | 인증서 개인키 유출이 A4-a와 A4-b를 동시에 의미한다. 자격 증명 무효화와 연쇄 폐기를 함께 수행한다 |

## 5. DB 쓰기 침해 (B3)

### 5.1 권한 수준

| 수준 | 정의 |
| --- | --- |
| R | 읽기만 (= B2) |
| W1 | 하나의 DB 역할이 가진 DML 권한(INSERT·UPDATE·DELETE 중 부여된 것)을 그 역할에 허용된 테이블에 행사. DDL 없음 |
| W2 | 애플리케이션이 사용하는 모든 DB 역할의 권한 합집합. 애플리케이션 DB 자격 증명 탈취와 같은 수준. DDL과 권한 재부여는 포함하지 않으며, 그러려면 애플리케이션 계정이 스키마 소유자가 아니어야 한다 |
| DBA | DDL, 권한 재부여를 포함한 관리자 권한 |

W1의 대표 사례는 애플리케이션 연결을 통한 SQL 주입이며, 이때 범위는 해당 DB 역할에 부여한 권한과 같다. W1 방어는 실제 역할에 허용된 INSERT·UPDATE·DELETE와 애플리케이션의 상태 변경 경로를 기준으로 검증한다. DB 역할 분리, 제약조건, 트랜잭션이 존재한다는 사실만으로 악의적 DML을 모두 방어한다고 표현하지 않는다.

| 2 보안 상태 | 토큰 폐기, 바인딩, 실패 횟수·잠금, 인증 성공, 결과 사용, 재전송 기록, 멱등성 기록 | 동시성·장애·재시작·W1에서 불변식 유지 |
| 3 감사 기록 | 감사 이벤트 | 증거. 제공하는 위변조 방지 수준을 문서화하고 그 이상을 주장하지 않는다 |

등급 1 보호는 두 층으로 구분한다. ① DB 행 자체의 변경을 막는 것(역할 권한), ② 변조된 정보를 인증·인가 판단에 사용하지 못하게 하는 것(사용 시점의 승인 근거·최신성 검증, 실패 시 해당 고객사 인증 거부). 필수 요구사항은 ②이며, ①은 W2·DBA에서 보장하지 않는다.

### 5.3 공격별 방어 수단의 범위

| 공격 | 예 | DB 제약·동시성 제어 | DB 역할 권한 분리 | 트리거 (추가 전용 강제) | HMAC·서명 | DB 외부 기준 |
| --- | --- | --- | --- | --- | --- | --- |
| INSERT | 토큰 기록 위조, 과거 서명 행 재삽입 | 방어 못함 | 권한 없으면 차단 | 무관 | 새 위조는 탐지, 재삽입은 못 막음 | 재삽입 탐지 |
| UPDATE | 인증 상태 변경, 실패 횟수 감소 | 방어 못함 | 권한 없으면 차단 | 변경 거부 가능 | 위조 탐지, 과거 값 복원은 못 막음 | 복원 탐지 |
| DELETE | 재전송 기록 삭제, 폐기 기록 삭제 | 방어 못함 | 권한 없으면 차단 | 삭제 거부 가능 | 삭제는 탐지 못함 | 누락 탐지 (외부 기준이 그 단위에 대응할 때) |
| DDL | 제약·트리거 제거 | 무력 | 무력 | 무력 | 탐지 유지 (키가 DB 밖) | 탐지 유지 |
| DBA | 위 전부 | 무력 | 무력 | 무력 | 탐지 유지 (키가 DB 밖) | 탐지 유지 (TA-6) |

DB 제약과 동시성 제어는 정직한 작성자가 동시에 쓸 때의 정합성을 지키는 장치이며, 악의적 쓰기를 막는 장치가 아니다.

| 2 보안 상태 | 불변식 유지 필수 | 필수 보장 아님. R-1·R-2로 연구 | 필수 보장 아님 |

## 6. 토큰·신뢰 정보 위조 시나리오 (S)

토큰 형식과 등록 정보 무결성을 평가하기 위한 시나리오다. 결과는 공격자가 침해한 것과 검증 측이 무엇을 신뢰하는가의 조합으로 정해진다.

| ID | 상황 | 대응 공격자 | JWT + 고객사 상태 확인 | JWT + 발급 기록 확인 (전체 해시) | Opaque + 발급 기록 확인 |
| --- | --- | --- | --- | --- | --- |
| S1 | 서명 키만 침해 | B4 | 위조 가능, 탐지 불가 | 기존 토큰의 복제만 통과. 원래 고객사 키에 묶여 이득 없음 | 해당 키 없음 |
| S2 | DB 쓰기만 침해 | B3 | JWT 서명 위조는 불가. 검증 측이 고객사 상태·폐기 기준을 DB에서 그대로 신뢰하면 보안 상태 조작은 가능 | 서명 위조 불가. 보안 상태 조작 가능성은 같음 | 기록 MAC이 없으면 위조 가능 |
| S3 | 서명 키 + DB 쓰기 | B4 + B3 | 위조 가능 | 위조 가능 | 위조 가능 (MAC 키까지 유출 시) |
| S4 | 과거 정상 기록 복원 | B3 (W2·DBA) | 상태 되돌리기로 부활 | 토큰 만료 전이면 부활 | 같음 |
| S5 | 고객사 등록 정보 변조가 별도 신뢰 검증 없이 수락됨 | B3 (등급 1) | 정상 발급 절차로 진짜 토큰 획득 | 같음 | 같음 |

- S3: 현재 검토 중인 R-1의 단조 증가 폐기 세대만으로는 방어하지 못한다.
- S4: R-1의 방어 대상이다.
- S5: 토큰 형식과 무관하며, 등록 정보를 사용 시점에 검증하면 차단 대상이 된다 (FR-AUTH-18).

## 7. 대표 연구 사례 (R)

모든 동적 데이터의 되돌리기 방어를 필수 구현하지 않고, 두 사례로 무결성·최신성·정합성·가용성의 Trade-off를 연구한다.

HMAC과 서명은 값의 출처를 증명할 뿐 그 값이 최신이라는 것을 단독으로 증명하지 않는다. 식별자와 용도를 인증 대상에 포함하면 다른 행으로의 바꿔치기는 방어할 수 있다. 막지 못하는 것은 같은 행의 과거 값 복원과 행 삭제다.

### R-1. 폐기된 자격 증명·상태의 복구

| 항목 | 내용 |
| --- | --- |
| 사례 | 비활성화된 고객사나 폐기된 키·토큰을 과거 상태로 되돌려 다시 사용 가능하게 만듦 |
| 대응 시나리오 | S4 |
| 연구 후보 | DB 밖에 단조 증가하는 폐기 세대를 두고 그보다 낮은 세대의 토큰·키를 거부 |
| 방어 범위 | 선정한 폐기 상태 복원 사례에 한정. TA-6 전제 |
| 한계 | S3, 모든 DB 복원 공격. 고객사 단위 세대 하나로는 그 세대를 올리지 않은 개별 키·토큰 폐기 기록의 삭제를 탐지할 수 없다. 개별 기록 단위의 탐지가 필요하면 외부 기준도 그 단위에 대응해야 한다 |
| Trade-off | 외부 기준과 DB의 갱신 순서·정합성 복구, 불일치 시 fail-closed와 가용성 |

### R-2. 사용된 인증 결과의 재사용

| 항목 | 내용 |
| --- | --- |
| 사례 | 이미 사용 처리된 인증 결과의 상태를 되돌려 다른 업무에 다시 사용 |
| 연구 후보 | 별도 자격 증명을 가진 추가 전용 기록 / 해시 체인 끝값의 외부 고정 / 짧은 사용 기한으로 피해 제한 |
| 한계 | 해시 체인 외부 고정은 마지막 고정 시점까지만 보호한다. 마지막 고정 이후의 기록이 변조되고 체인까지 다시 계산되면, 다음 고정 시점에 변조된 체인이 그대로 고정되어 이후에도 탐지하지 못할 수 있다 |
| 상태 | 실험 전에는 예방·탐지 효과를 주장하지 않는다 |

## 8. 방어 수단별 적용 범위

| 수단 | 막을 수 있는 것 | 막을 수 없는 것 |
| --- | --- | --- |
| DB 제약 | 동시성 정합성, 형식 위반 | 형식이 맞는 악의적 쓰기, 되돌리기 |
| DB 역할 권한 분리 | 권한 없는 W1의 쓰기 | W2, DBA |
| 트랜잭션·잠금 | 동시성, 장애 시 원자성 | 악의적 쓰기 |
| 트리거 (추가 전용) | DDL 없는 공격자의 수정·삭제 | DDL, DBA |
| HMAC·서명 | 위조 (키가 DB 밖일 때), 식별자·용도를 포함하면 바꿔치기 | 같은 행의 과거 값 복원, 삭제 |
| 버전 번호 | 외부 기준과 함께일 때 되돌리기 탐지 | 단독으로는 막지 못함 |
| 감사 기록 | 사후 확인 | 단독으로는 충분하지 않음 |
| DB 외부 신뢰 기준 | 되돌리기 (전제 충족 시) | 외부 기준 자체의 침해, S3 |

## 9. 분류

### 9.1 필수 방어·검증

- A1, A2, A3-a, A3-b (업무 API와 토큰 엔드포인트의 요청 무결성), A4 사고 대응, A5 피해 제한
- B1, B2 피해 제한, B3 (등급 1 신뢰 정보의 위조 방어, 등급 2 불변식의 동시성·장애·재시작·W1), B4, B5, B6 기본 운영 보안
- **재전송 방지와 장애 이후 중복 수락 방지** (D-X50, NFR-SEC-11)
- 표준 요구사항: Client Assertion의 aud 요구, Access Token의 대상 서버 검증, 다운그레이드 방어

### 9.2 기술 비교·실험으로 연구

- A3 응답 무결성, R-1, R-2, 감사 기록 외부 고정, 외부 기준 불일치 시 fail-closed와 가용성의 Trade-off
- 필수 요구사항을 충족하기 위한 **구현 수단의 비교** (재전송 저장소 구성, 조건부 안전 대기, 저장소 복구 방식, 등록 정보 최신성 기준). 수단이 연구 대상이라고 요구사항이 선택 사항이 되는 것은 아니다

### 9.3 현재 신뢰 가정에서 보장하지 않음

- 호스트 Root 획득, 애플리케이션 전체 장악, 고객사 서버 장악의 예방
- DB 외부 기준 없는 동적 데이터의 DBA 되돌리기
- 외부 고정 없는 업무 데이터와 감사 기록의 동시 변조
- S3 (서명 키와 DB 쓰기의 동시 침해)
- 평문 접근 지점을 장악한 경로 공격자에 대한 기밀성, 경로 공격자의 차단·지연에 대한 가용성
- 고객사 측에서 응답을 검증하지 않는 경우의 응답 위변조

경로 공격자에 대한 기밀성을 필수로 보장하지 않는다는 것은, 종단 간 TLS로 기밀성을 보호할 수 없다는 뜻이 아니다. TLS가 애플리케이션까지 이어지면 프록시에서는 평문 노출 자체가 없다.
