## 2. 상태와 근거

| 축 | 값 |
| --- | --- |
| 의사결정 상태 | 확정 / 우선 후보 / 검토 중 / 미결정 / 제외 / 대체됨 |
| 근거 유형 | 판단 / 명세 확인 / 소스 확인 / 실행 검증 |
| 실행 검증 상태 | 미검증 / 검증 예정 / 검증 통과 / 검증 실패 / 검증 불충분 / 해당 없음 |

| 근거 유형 | 남길 것 |
| --- | --- |
| 명세 확인 | 문서 버전, 절 번호, 원문 링크, 규범 수준 |
| 소스 확인 | 저장소, 태그 또는 커밋, 파일, 관련 동작 |
| 실행 검증 | 테스트 코드, 실행 환경, 실제 결과 |

명세나 소스를 확인했다는 사실만으로 실행 검증이 완료됐다고 표현하지 않는다. 검증 상태는 실행 증거가 있을 때만 바꾼다.

## 3. 식별자

- 변경하거나 재사용하지 않는다.
- 새 항목에는 새 식별자를 부여한다.
- 제외되거나 대체된 항목도 이력을 유지하고 후속 식별자를 연결한다.

## 4. 문서 변경

| 항목 | 규칙 |
| --- | --- |
| 결정 변경 | 결정 대장과 관련 문서를 같은 PR에서 갱신하고 변경 이력을 추가한다 |
| status.md | Sprint Review, 관문 완료, 중요 결정 변경, 작업 중단·재개 때 갱신한다 |
| 금지 | 측정하지 않은 성능 수치, 검증하지 않은 보안 주장 (NFR-OPS-04) |
| 공개와 로컬 | 개인 개발 도구 설정과 인수인계 절차는 로컬 전용 파일로 관리하고 커밋하지 않는다 (D-O23). 설계 과정의 대화 원문은 공개하지 않는다 |

## 5. ADR

| 항목 | 규칙 |
| --- | --- |
| 위치 | docs/adr/NNNN-제목.md |
| 상태 | 제안 / 채택 / 대체됨 / 기각 |
| 본문 | Context, Alternatives, Decision, Rationale, Consequences, Verification |
| 작성 시점 | 새 기술 도입(NFR-ARCH-04), Phase 3 기술 선택, 대안 비교가 있었던 확정 결정 |
| 검증 | 동작을 근거로 하는 결정(보안 기술, 저장소 선택 등)은 실행 검증 결과를 연결한다. 실행 검증이 적용되지 않는 결정(브랜치 전략, 문서 관리 정책 등)은 대안과 판단 근거를 기록하고 검증은 해당 없음으로 둔다 |
| 채택하지 않은 후보 | 확정 ADR로 쓰지 않는다 |
| 변경 | 채택된 ADR의 내용은 수정하지 않고 후속 ADR로 대체한다. 서로 링크한다 |
| 결정 대장과의 관계 | 서로 참조한다 |
