# AI 코드 리뷰

기준일: 2026-11-26

## 1. 도구

최종 구성은 실제 이용 조건, 비용, 권한을 확인한 뒤 결정한다 (U-20).

| 도구 | 위치 | 비고 |
| --- | --- | --- |
| CodeRabbit | 기본 리뷰어 우선 후보 | 공개 저장소라고 해서 무료 이용 조건을 자동으로 충족하는 것은 아닐 수 있으므로 연동 전에 라이선스와 이용 자격을 확인한다. 조건에 따라 리뷰를 수동으로 요청해야 할 수 있다 |
| Claude 기반 Actions | 보조 리뷰어 후보 | 보안 영향이 큰 PR에 수동 호출. 저장소의 공통 규칙(AGENTS.md)을 기준으로 리뷰하도록 구성한다 |
| GitHub Copilot | 이용 조건 충족 시 비교 | — |

자동 리뷰와 수동 요청 리뷰를 구분해 비교한다.

## 2. 대응 절차

| 단계 | 규칙 |
| --- | --- |
| 판정 | 댓글마다 반영 / 미반영 / 보류 |
| 근거 | 실제 코드, 공식 명세, FR·NFR, 위협 모델, ADR 중 해당 근거를 식별자로 남긴다. AI 리뷰를 무조건 수용하지 않는다 |
| 보류 | 중요도와 후속 이슈를 남긴다 |
| 해결 | 판정과 근거를 답글로 남긴 뒤 대화를 해결한다 |
| 병합 조건 | 필수 보안 결함이 해결되지 않으면 병합하지 않는다 |
| 재리뷰 | 리뷰 이후 추가 커밋으로 변경된 부분은 필요하면 다시 리뷰한다 |

## 3. 자기 리뷰와의 관계

- 자기 리뷰와 AI 리뷰는 별개다. AI 리뷰는 사람의 판단이나 필수 보안 검증을 대체하지 않는다.
- 이용 한도나 도구 장애로 AI 리뷰를 받지 못하면 PR에 사유를 기록하고 자기 리뷰와 필수 검증을 수행한다.
- AI 리뷰 미수행을 필수 보안 검증 실패와 같게 취급하지 않는다.

## 4. 작성자 표시

리뷰 봇이 PR에 댓글을 남기는 것은 허용한다. 커밋의 공동 작성자 표시와 PR 본문의 자동 생성 문구는 넣지 않는다 (D-O14).

## 5. 보안 검토 능력 비교 실험 (D-V08)

- 의도적인 결함은 가상 데이터와 격리된 실험 코드에만 넣고 정식 서비스에 병합하지 않는다.
- 결과는 정확한 지적 / 오탐 / 미탐 / 잘못된 근거로 구분해 기록한다.
