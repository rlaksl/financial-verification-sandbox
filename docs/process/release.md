# Release와 완료 기준

기준일: 2026-11-26

## 1. Release

| 항목 | 규칙 |
| --- | --- |
| 대상 | 정식 서비스 버전. Phase 0 ~ 3은 Release 없이 문서 결과로 종료한다 |
| 태그 | Annotated Tag. Phase 종료 `phase-0-complete` ~ `phase-3-complete`(GitHub Release 없이 보관), 정식 버전 `v0.1.0` 형식. 검증과 병합이 끝난 main 커밋에만 생성하고 임의로 수정·삭제하지 않는다 (D-O32). 서명 여부는 U-35 |
| Release Notes | 구현한 FR, 검증한 보안 요구사항, 알려진 한계, 관련 ADR, 검증 결과 문서 |
| 금지 | 측정하지 않은 성능 수치, 검증하지 않은 보안 주장 |

## 2. Milestone 종료 조건

상세 기준은 [요구사항 문서](../requirements/requirements.md) 7절이다.

| Milestone | 확인 |
| --- | --- |
| Phase 0 | 설계 문서 검토 완료, 초기 저장소 설정, Projects·Milestone·첫 Sprint 설정, 초기 CI 실행과 실패 시 병합 차단 확인 |
| Phase 1 | 관문별 판정 상태 기록 |
| Phase 2 | 필수 시나리오 통과 후보의 비교 결과 기록 |
| Phase 3 | 채택 계열의 ADR 채택, 채택 보류·불가 후보의 근거 기록 |
| v0.1 ~ v0.4 | 기능 구현, 적용 가능한 보안 요구사항 검증, 테스트, CI, 문서 반영 |
| v1.0 | 요구사항 문서 7.4 |
| v1.1 | 별도 테스트 클라이언트를 외부 고객사처럼 사용한 연동과 장애 복구 검증 (U-31) |
| v1.2 | 모의 휴대폰 본인확인 구현과 검증, 기존 기능 회귀 테스트 |

## 3. 일정

12/11은 일정 관리상의 목표일이며 기술적 완료 조건이 아니다. PoC 결과와 실제 작업량에 따라 일정을 재산정할 수 있고, 일정 때문에 필수 보안 요구사항이나 검증 범위를 줄이지 않는다 (D-P08).
