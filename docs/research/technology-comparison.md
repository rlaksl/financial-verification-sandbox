## 0. 문서 기준

### 0.1 역할

유지 중인 후보를 같은 요구사항과 같은 평가 기준으로 비교한다. PoC 전이므로 성능이나 구현 가능성의 우열은 확정하지 않는다. 결정은 [결정·상태 대장](../decision-register.md), 근거 원문은 [명세·소스 분석 기록](spec-source-analysis.md)에 있다.

## 1. 계열 비교

계열은 고객사 인증, 토큰 사용 주체 제한, 요청 무결성을 묶은 조합이다.

| 기준 | M-1 tls_client_auth + 인증서 바인딩 | M-2 self_signed_tls_client_auth + 인증서 바인딩 | M-3 private_key_jwt + 인증서 바인딩 | D private_key_jwt + DPoP + RFC 9421·9530 |
| --- | --- | --- | --- | --- |
| A1 | 인증서 바인딩 [판:충족 가능] | 같음 | 같음 | DPoP 바인딩 [명 SPEC-16] [판:충족 가능] |
| A2 | 0-RTT 검토 필요 [미 SPEC-64·65] | 같음 | 같음 + Assertion 재전송 기록 [소 SRC-07] | Assertion·DPoP·메시지 서명 재전송 기록 [판] |
| A3 요청 무결성 | TLS가 애플리케이션에서 종료될 때 연결 단위 보호 [판:충족 가능] | 같음 | 같음 | RFC 9421 + 9530 직접 구현 [소 SRC-30] [판:충족 가능] |

| A4-a·A4-b | 인증·바인딩 자격 증명이 같아 중첩 [판] | 같음 | 분리 [판] | 분리 [판] |

| 바인딩 강제 | cnf 없는 토큰 거부를 직접 보장해야 함 [소 SRC-24] | 같음 | 같음 + 발급 커스터마이저 [소 SRC-23] | DPoP 필수화 직접 구현 [소 SRC-11, SRC-32] |

| 장애 대응 | 폐기 정보 조회 실패 정책 (T-27) | 같음 | 같음 + 재전송 저장소 | 재전송 저장소 fail-closed 경로 다수 [판] |
| 성능 | [측정] | [측정] | [측정] | [측정] |
| 관문 | G1-a ~ c, G3-a | G1-a ~ c, G2, G3-b | G1-a ~ c, G4 | G5, G6, G7 |

토큰 발급·폐기·감사 기록은 모든 계열에서 필요하다.

**M-3의 평가 관점**: 고객사 인증 자격 증명과 토큰 바인딩 자격 증명의 수명주기를 독립적으로 관리할 수 있는 가능성. 인증서 지문이 바뀌면 기존 인증서에 바인딩된 토큰은 그대로 사용할 수 없다. M-2 대비 추가로 막는 공격은 아직 찾지 못했다 [판].

우열은 관문 결과 이후에 판단한다.

## 5. 요청·응답 무결성

### 5.1 업무 API

| 기준 | 종단 간 TLS·mTLS | DPoP 단독 | DPoP + 사용자 정의 Claim | RFC 9421 + 9530 | DPoP + RFC 9421 |

| Idempotency-Key | 보호 [판] | 미보호 | 넣으면 보호 [판] | 서명 대상이면 보호 [판] | 같음 |

| 재전송 식별자 | — | jti | jti | 메시지 서명 식별자 | 통합은 조건부 (D-X45) |

DPoP와 메시지 서명을 함께 쓸 때 겹치는 기능: 요청마다의 키 보유 증명, 생성 시각, 재전송 식별자, 메서드·URI. 함께 쓰는 이유는 DPoP가 토큰을 키에 묶는 표준 방식과 프레임워크 지원을, 메시지 서명이 메시지 무결성을 제공하기 때문이다 [판]. 메시지 서명만으로 부인 방지를 주장하지 않는다 (D-X44).

## 6. 재전송 저장소

### 6.1 공통 원칙

- 필수 요구사항(NFR-SEC-11)은 어떤 구성에서도 같다.
- 보안 재전송 기록은 모든 구성에서 업무 트랜잭션과 분리하며 업무 롤백으로 되돌리지 않는다 (D-X54).
- Idempotency-Key와 operationId는 모든 구성에서 PostgreSQL 업무 트랜잭션으로 처리한다 (D-X53).
- 저장소를 분리했다는 사실만으로 신뢰 경계가 분리됐다고 보지 않는다. 실제 자격 증명과 접근·운영·복원 권한을 기준으로 W1·W2 범위를 정의한다.

### 6.2 구성별 데이터 배치

| 데이터 | P PostgreSQL 중심 | H 혼합 | R 재전송 방지 Redis 중심 |
| --- | --- | --- | --- |
| Idempotency-Key, operationId | PostgreSQL 업무 트랜잭션 | 같음 | 같음 |
| Assertion jti | PostgreSQL (업무와 별도 트랜잭션) | 데이터 특성에 따라 배치 | Redis |
| DPoP jti, 메시지 서명 식별자 | PostgreSQL (별도 트랜잭션) | 데이터 특성에 따라 배치 | Redis |
| 요청 제한 기록 | T-32 결과에 따름 | 같음 | 같음 |

H의 배치 기준은 비교 실험 전에 정한다.
